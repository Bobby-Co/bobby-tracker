# replay.sh diffs the replayed schema against this to surface two kinds of drift
# that a clean replay alone cannot detect:
#
#   * a table the migrations create that production does NOT have  → a migration
#     that was never applied (or a table dropped by hand). Code that writes to it
#     is broken in production right now.
#   * a table production has that no migration creates → someone else's DDL. In
#     practice that is bobby-analyser, which writes into the `tracker` schema
#     using its own credentials and has no entry in this repo's migrations. That
#     is the root cause of the issue_embeddings partitioning drift too, and it
#     will keep happening until the analyser's tracker-schema DDL is recorded
#     somewhere both services agree on.
